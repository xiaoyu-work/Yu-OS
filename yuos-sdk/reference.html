app.json Manifest & Parameter kind Reference

Every Yu OS App declares its metadata, parameters, and permissions in app.json. Command-line and desktop launches share operations.

When your App calls app.log(message, level="info") (or accesses app.data_dir()), logs are both printed live and persisted to disk:

Permissions

Declare permissions in the needs array of each operation or MCP tool in app.json. AI permissions take no scope and can be written as strings ("needs": ["ai.chat"]). User-supplied files (CLI "kind": "path" arguments and gui.open_file() selections) automatically receive read access without needing a needs entry.

PermissionScopeDescription
ai.chat, ai.embed, ai.audio.tts, ai.audio.stt, ai.image.generate, ai.decideNone (string shorthand)Call the corresponding ai.* model capability.
fs.read, fs.write, fs.delete, fs.meta, fs.watchowner-path / from-arg / app-dataRead, write, delete, stat, or watch files in the declared path scope.
ui.promptfixed (save-file / select-folder)Open the native Save dialog or Folder picker.
ui.notifywildPost desktop notifications.
net.dial, net.resolve, net.probehost / wildOutbound network connections and DNS lookups.
net.listenhost / wildBind a local listening socket.
device.camera, device.microphone, device.audio, device.location, device.bluetooth, device.printerwild / nameAccess camera, microphone, audio, location, Bluetooth, or printer hardware.
desktop.capturewildCapture screenshots or screen recordings.
desktop.media.observe, desktop.media.controlwildObserve or control active media playback.
clipboard.read, clipboard.writename (selection / history)Read or write the clipboard.
data.kv.*, data.log.write, ipc.publishapp:<id>Access App-owned KV storage, structured logs, and domain event publishing.

App-Owned AI Functions (Tool Calling)

Pass function schemas in functions to chat. The model proposes a tool call in reply.output.tool_calls; your App validates and executes the function under its own permissions and sends the result back in tool_turns.

Object References & Domain Events

  • Object references (objects): Format and parse canonical app://<app-id>/<type>?id=<id> URIs using format_reference / parse_reference.
  • App events (events): Publish structured domain events under ipc.publish (app:<id>) using events.publish(event_type, idempotency_key, entity_id=..., payload=...).
