Permissions, Error Codes & CLI Reference

How Yu OS isolates Apps, maps permissions to macOS and Windows, handles AI error codes, and packages Apps for the Store.

App Permissions vs. System Permissions

Like macOS and Windows, Yu OS separates App permissions from system permissions. AI permissions need no extra fields and can be written as strings ("needs": ["ai.chat"]). User-supplied files (CLI "kind": "path" arguments and gui.open_file() selections) automatically receive read access by user intent without needing a needs entry.

Every other capability (such as sys.*, secret.*, agent.*, browser.*, proc.*, fs.exec, net.manage, net.firewall, data.log.read) is a system permission. Official Yu OS Apps keep them; for third-party Apps, an administrator must approve each use (in a terminal, yu prompts for the administrator password in place like sudo and reuses it for 5 minutes).

App-Owned AI Functions (Tool Calling)

Pass function schemas in functions to chat. The model proposes a tool call in reply.output.tool_calls; your App validates and executes the function under its own permissions and sends the result back in tool_turns.

Object References & Domain Events

  • Object references (objects): Format and parse canonical app://<app-id>/<type>?id=<id> URIs using format_reference / parse_reference.
  • App events (events): Publish structured domain events under ipc.publish (app:<id>) using events.publish(event_type, idempotency_key, entity_id=..., payload=...).
